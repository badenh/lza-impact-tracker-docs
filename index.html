About (LZA, LZA UC and LZA CW)

The AWS Landing Zone Accelerator (LZA) Universal Configuration (UC) is an Infrastructure-as-Code package developed from years of field experience with highly regulated customers including governments across the world, and in consultation with AWS Partners and industry experts. The Universal Configuration was built to help AWS customers (and the partners who assist them) to implement security and compliance at scale on regulated workloads. By setting a high bar with the latest AWS security best practices, the Universal Configuration can help address technical control requirements from compliance frameworks across different geographic regions and industry verticals.

The AWS LZA Compliance Workbook maps every LZA Common Control ID to one or more controls in a growing set of industry-recognized Compliance Frameworks.

The LZA Compliance Workbook is organized LZA-first — each row has an LZA Common Control ID and then a Compliance Framework column with packed identifiers; this presentation makes framework-side questions ("how many LZA controls cover ISO 27001 A.8.16?") awkward to answer at a glance. Equally the Compliance Workbook is fundamentally oriented toward selecting and working with a single framework; this presentation makes a comparison of the coverage and impact of LZA against a set of frameworks — even those that have well understood relationships to each other — less straightforward.

This tool (LZA CFIT) inverts and normalizes the mapping across every published workbook version, then lets you slice it interactively: by version, framework, LZA control, or a specific framework control. All counts are raw mapping counts, not implementation-depth or compliance assurance metrics — see caveats at the bottom.

How is a mapping tuple counted?

A mapping tuple is a single (LZA Common Control ID, framework, related control) triple emitted from the workbook.

For each row of the Mapping Rows Merged sheet (one LZA Common Control ID) and each framework column, the cell contents are split into individual related-control identifiers — newline, comma, or space delimited depending on the framework, with parenthetical control-enhancement fragments like AC-2 (1) preserved. Sentinel values (NA, N/A, None, Nil, -, No Control Mapping) yield zero tuples. One tuple is emitted per resulting identifier.

Example: an LZA row with the ISO 27001 column containing A.5.3\nA.5.9\nA.5.10 produces three tuples. Duplicate identifiers within a single cell (a workbook defect) are not deduplicated and count once per occurrence. The count reflects the shape of AWS's mapping, not implementation depth.

    Caveats

    • LZA CFIT is not a product or service offered by AWS; it is an independently developed analytical layer developed over AWS security and compliance materials which are available to any/all AWS customers.
    • Names of Compliance Frameworks are displayed in the form they appear in the LZA Compliance Workbook — typically a commonly recognized acronym or abbreviation.
    • The workbook does not enumerate every control in each framework — only those for which a mapping has been created between a LZA Common Control ID and a compliance framework specific ID. Framework-side denominators for a coverage percentage are not derivable from this data alone.
    • The workbook does not contain the narrative of each framework control.
    • Counts reflect the breadth of the mappings in the LZA Compliance Workbook — not implementation depth or quality of security outcome. A high count is not evidence of thoroughness and LZA CFIT makes no assertion regarding level of compliance with any particular framework for any particular purpose.
    • For a detailed analysis of coverage and rating, see separate AWS Security Blog posts and Artifact reports by Compliance Framework, e.g. ISM Australia, C5 Germany, CCCS Canada.
    • To download the LZA Universal Configuration, please access it via GitHub.
    • For official AWS support re LZA, please contact the LZA team directly using this form.
